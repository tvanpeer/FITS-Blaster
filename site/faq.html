Getting Started

What macOS version is required?

macOS 15.6 (Sequoia) or later.

Does FITS Blaster run on Intel Macs?

It will run, but performance will be significantly lower. FITS Blaster uses Apple's Metal GPU framework for stretching, star detection, and metrics computation. Metal works best on Apple silicon (M1 and later). Intel Macs with integrated graphics lack the GPU memory bandwidth to keep up with large image sets; loading times will be several times slower.

Is there a Windows or Linux version?

No. FITS Blaster is a native macOS application and uses macOS-specific frameworks (Metal, Accelerate, AppKit). There are no plans for a Windows or Linux port.

Does FITS Blaster require an internet connection?

No. Image loading, stretching, and all quality measurements work entirely offline. However, FITS Blaster checks for updates once every 24 hours in the background. This is a lightweight check and can be skipped or disabled in the update prompt. If no connection is available, the check is silently skipped and the app works exactly the same.

Can I try FITS Blaster without my own images?

Yes. Download the M31 sample set (255 MB zip): eight raw 120 s light frames of the Andromeda Galaxy from one night, taken with a one-shot colour camera (ATR2600C, RGGB Bayer pattern) on a William Optics Zenithstar 73.

Unzip it, click Open Folder… in the toolbar, select the FITS-Blaster-Sample-M31 folder and click Open. The included README.txt lists how PixInsight's SubframeSelector rates each frame, so you can compare its ranking with FITS Blaster's. Two frames were taken through thin cloud.

Loading Images

How do I open images?

There are three ways to load images into FITS Blaster:

  1. Open Folder… button or ⌘O — the folder panel opens with two checkboxes: Include files from subfolders and Include REJECTED folder (loads previously rejected frames, marked as rejected). Choose one folder or several and click Open. The checkboxes start from your defaults in Settings → Files & Folders; changes in the panel apply to this time only.
  2. Drag & drop onto the window — drag a folder or any number of FITS files from Finder and drop them onto the FITS Blaster window.
  3. Drag & drop onto the app icon — drag files or a folder onto the FITS Blaster icon in the Dock or in Finder to open them directly, even if the app is not running yet.
What FITS formats are supported?

FITS files with integer pixel data: BITPIX 8 (8-bit), BITPIX 16 (16-bit), and BITPIX 32 (32-bit). Floating-point FITS (BITPIX −32 or −64) are not supported and will be skipped with an error message. The supported extensions are .fits, .fit, and .fts.

Can I preview FITS files in Finder?

Yes. FITS Blaster installs Quick Look extensions, so Finder shows thumbnails for FITS files, and pressing the spacebar on a file shows a stretched preview. This also works for files the app itself doesn't load: floating-point FITS (BITPIX −32 and −64) and 3-channel colour FITS such as stacked integrations, including files over 1 GB.

FITS files in iCloud Drive only get a thumbnail once they are downloaded to your Mac. To keep thumbnails for an iCloud folder, choose Keep Downloaded on it in Finder.

Will you support other image formats, like Canon RAW?

Not at this time. FITS Blaster is purpose-built for FITS files as used in astrophotography. RAW camera formats (CR3, NEF, ARW, etc.) are not on the roadmap.

How many images can FITS Blaster load?

In practice, as many as your RAM allows. It has been tested with up to 592 images without issues on a MacBook Air M1 with 16 GB — see the Speed & Performance section below for details.

Can I open images from subfolders?

Yes. Click Open Folder… (or press ⌘O) and turn on Include files from subfolders in the folder panel. FITS Blaster will scan recursively and display each subfolder as a separate section in the sidebar. By default, calibration folders (FLAT, DARK, BIAS, CALIB) are skipped automatically; you can customise the exclusion list in Settings → Files & Folders.

What are filter groups?

When FITS Blaster loads images from a session with multiple filters (for example Ha, OIII, and broadband frames in the same folder), it reads the filter name from the FITS header and automatically groups frames by filter in the sidebar. Each group gets its own colour-coded section, making it easy to assess quality separately per filter — a frame that is fine for Ha may still be worth rejecting for OIII.

If no filter information is present in the headers, all frames appear in a single group.

Should I use colour or greyscale display?

Greyscale loads and renders much faster and is usually all you need for judging star shape, focus, and trailing. FITS Blaster always loads greyscale first, so you can start culling immediately regardless of display mode.

Colour mode debayers OSC (one-shot colour) images and shows them in full colour, which can be useful for checking gradients, satellite trails, or colour artefacts. Colour rendering takes roughly 2–3× longer per image. Both the colour and greyscale versions are kept in memory once loaded, so switching between them is instant. With very large sessions, the frames you looked at least recently give up their display images when the memory limit is reached (Settings → Display → Memory) and are drawn again when you return to them.

Mono (greyscale) cameras are always displayed in greyscale regardless of the display setting.

Does FITS Blaster modify my images?

Never. FITS Blaster is strictly read-only. Pixel data is loaded into a separate display buffer; the original files are never written to. The only file operation FITS Blaster performs is moving rejected frames into a REJECTED/ subfolder — and that move is fully undoable. With Rename rejected files so other programs skip them on (Settings → Files & Folders, off by default), the moved file also gets .rejected after its name; undo restores the old name. The image data is never changed.

What happens when I press Reset?

Reset clears the current session so you can immediately open a new folder. It does not delete or move any files.

Viewing Images

How do I zoom in and out?

Four ways:

  • Keys — = zooms in, − zooms out, 0 fits the image in the viewer and 9 shows it at 100 %; ⌥+arrow keys pan. The same actions are in the View menu.
  • Zoom slider — the slider in the display controls bar below the image (range 0.25×–4×). Click the zoom icon or the percentage label to jump to 1:1 (100 %).
  • Zoom to fit — the fit button (↖↘ arrows) next to the zoom percentage scales the image to fill the viewer without scrolling.
  • Trackpad pinch — pinch to zoom in or out directly on the image.

The keys, the slider and pinch keep the current centre of the viewport fixed as you zoom, so you don't lose your place.

How do I zoom into a specific star or detail and keep it in view?

Use the zoom anchor. Click anywhere on the image to pin that point — a small crosshair appears. All subsequent zoom changes (keys, slider or pinch) will keep that point centred in the viewport.

  • Move the anchor: click a different spot.
  • Clear the anchor: click the crosshair again (within about 20 px of it), or press the Defaults button in the display controls bar.
  • Re-centre after scrolling: click the lit scope (⊕) icon in the zoom controls — it scrolls the anchor back to the centre without clearing it.

The anchor persists across image navigation. Because all frames in a session cover the same field, the same position points to the same star or region in every frame — useful for comparing star shape across a run.

What is the Target Background slider?

The Target Background slider sets the desired brightness of the sky background in the displayed image, on a scale from 0.05 to 0.50.

FITS Blaster's automatic stretch (STF) always targets a background level of ~0.25, so the default value of 0.25 produces no visible change. Adjust it when you want a different look:

  • 0.10–0.15 — darker sky, more contrast; good for images with a relatively dark background.
  • 0.25–0.40 — brighter background; useful for images with large extended objects (wide nebulae, galaxies) where you want to preserve mid-tone detail.

The value persists across app restarts. This control is analogous to the Target Background parameter in PixInsight's Multiscale Adaptive Stretch.

What does the Stretch slider do?

The Stretch slider is a post-stretch contrast multiplier (0.5×–3.0×, default 1.0×). Increasing it brightens mid-tones and brings out faint detail; decreasing it flattens contrast. Unlike Target Background, it resets when you open a new session.

Image Quality Metrics

What does the Score badge mean?

Each frame's badge shows its score, coloured by the worst problem found, compared with the other frames of the same filter group:

  • Red — trailing (elongated stars) or a focus problem (FWHM well above the group's median)
  • Amber — a low star count compared with the group (haze, thin cloud, dew)
  • Green — no problem found, and the score is in the top third of the group
  • Grey — no problem found, not in the top third

When a frame has more than one problem, the badge shows the first of: trailing stars → focus failure → low star count. The exact limits are on the Scores page.

What is FWHM?

Full Width at Half Maximum — a measure of how sharp (tightly focused) the stars are. It is the diameter of a star profile at half its peak brightness, in sensor pixels. Lower is better: a well-focused session might have FWHM 3–5 px, while a poorly-focused or turbulent frame might be 8–10 px or more.

FITS Blaster fits a Moffat β=4 profile (the same default as PixInsight's SubframeSelector) along four directions (0°, 45°, 90° and 135°), reconstructs the star's major and minor axes from them, and reports the geometric mean of the two. Results agree with PixInsight Moffat4 within ±10% under typical conditions.

What is Eccentricity?

Eccentricity measures how elongated the stars are (0 = perfectly round, 1 = infinitely elongated). Normal frames measure about 0.4 on mono cameras and 0.5 on colour cameras; above about 0.65 stars are clearly elongated (the red trailing badge), and star trails measure 0.9 and up. Elongation comes from poor polar alignment, guiding errors, wind shake, or a mechanical issue.

FITS Blaster fits a 1D Moffat β=4 profile along four directions (0°, 45°, 90°, 135°) and uses the measurements together to reconstruct the true major and minor axes of the PSF ellipse analytically — at any orientation. Eccentricity is then e = √(1 − (FWHM_minor / FWHM_major)²). This approach detects elongation at any angle with equal sensitivity, including diagonal trailing.

Colour (OSC/Bayer) cameras: each star crop is bilinearly demosaicked using adaptive per-channel sky weights before the four-direction Moffat fit. Adaptive weights balance Ha and OIII signal in dual-narrowband images, so the axis-ratio measurement is accurate regardless of filter type. Eccentricity precision on OSC cameras is equivalent to a mono camera.

What is SNR?

Signal-to-Noise Ratio — the total light of each star (from the fitted profile) divided by the sky noise; the frame's value is the median over its measured stars. Higher is better. SNR follows exposure length, transparency and sky brightness, so it drops with haze and thin cloud; unlike PSF Signal Weight it doesn't change with the seeing. Session medians are typically 1 000–10 000. It is most useful for comparing frames within the same session rather than between different nights or setups.

What is PSF Signal Weight (PSF·S)?

PSF Signal Weight is a metric computed alongside the Moffat PSF fit. It measures peak amplitude per unit of sky noise, rewarding both good transparency and good seeing.

The formula is PSF-SW = mean(A) / σ_sky, where A is the background-subtracted sub-pixel peak brightness of each star and σ_sky is the sky noise from Step 1.

Good transparency delivers more photons, raising A. Good seeing concentrates photons into a narrower PSF, also raising A. As a result:

  • High PSF·S — good transparency and/or good seeing. Stars are bright and sharp relative to the sky noise.
  • Low PSF·S — haze, thin cloud, poor seeing, or high sky background. The frame was photon-starved or the PSF was bloated.
  • Compared with SNR: SNR uses each star's total light, PSF·S its peak. Both drop with haze and thin cloud; only PSF·S also drops with poorer seeing.

PSF Signal Weight appears in the session chart (PSF·S button), the inspector panel, and the sidebar sort menu. It is a supplemental metric and does not contribute to the composite quality score.

Why are FITS Blaster's FWHM values different from my other tools?

FWHM is not a standardised measurement — every tool makes different choices about the PSF model, fitting method, and unit convention. Agreement within ~10% is normal. The most common causes of larger differences are:

  • Different PSF models: FITS Blaster and PixInsight use Moffat β=4; Siril fits β as a free parameter (typically 3–4). When β < 4, Siril's free-β fit finds a tighter core and reports a lower FWHM.
  • Gaussian vs Moffat: A Gaussian PSF has lighter wings than a Moffat profile, so Gaussian FWHM estimates are often slightly larger.
  • Units: Siril reports FWHM in arcseconds by default. To convert: FWHM (px) = FWHM (″) / plate_scale, where plate_scale = 206.265 × pixel_size_µm / focal_length_mm.
  • 1D vs 2D fitting: FITS Blaster fits 1D profiles in four directions and combines them into the star's two axes. PixInsight and Siril fit a full 2D PSF simultaneously.

For frame ranking (the primary use case), absolute accuracy matters less than consistency. FITS Blaster is self-consistent within a session and correlates reliably with actual image quality.

Does FITS Blaster correct FWHM for Bayer (OSC) cameras?

Yes. FITS Blaster reads the BAYERPAT FITS header (also COLORTYP and CFA_PAT) and, when a Bayer pattern is detected, bilinearly demosaicks each star crop to a full-resolution luminance image before fitting the Moffat profile.

FWHM and eccentricity use different luminance weights, chosen to match how each metric is effectively measured by PixInsight SubframeSelector:

  • FWHM uses ITU-R BT.709 weights (wG = 0.7152). Because G pixels make up 50 % of any Bayer mosaic, PixInsight's PSF fit is naturally G-dominated. Matching this weighting gives FWHM rankings that agree closely with PixInsight's (Spearman r ≥ 0.95 on tested narrowband and broadband datasets).
  • Eccentricity uses adaptive per-channel weights estimated from the outer-border sky brightness of each crop. This correctly balances Ha and OIII signal in dual-narrowband images (such as an Antlia ALP-T filter), where all three Bayer channels carry real star flux.

FWHM values are at native pixel scale — no scale-back factor is applied.

Culling Frames

What does a typical culling session look like?
  1. Open your folder — use ⌘O or drag it onto the window. FITS Blaster starts loading and measuring quality metrics immediately; you can begin reviewing before the full set has loaded.
  2. Scan the session chart — the horizontal strip across the bottom plots all frames in time order, one colour per filter. A run of frames above or below their filter's dashed median line usually points to a specific problem period (clouds, a focus drift, a gust of wind).
  3. Review suspect frames — click a dot in the chart to jump to that frame, or step through the sidebar with the arrow keys. The main view shows the stretched image; the inspector on the right shows the exact metric values.
  4. Collect suspect frames — drag across the chart, or select a range in the sidebar (⇧+click, ⌘+click) and press F to add them to the Flagged view. Auto-Flag can also flag frames below a quality threshold automatically.
  5. Inspect and reject — switch to the Flagged view in the sidebar to see only your flagged frames. Step through them, then press your reject key (default: X) to move the bad ones to REJECTED/.
  6. Hand off to your stacking tool — point PixInsight, Siril, or AstroPixelProcessor at the same folder. The rejected frames are now in REJECTED/. A tool that also reads subfolders, such as PixInsight's WBPP with a directory, would find them there: turn on Rename rejected files so other programs skip them in Settings → Files & Folders, so they end in .rejected and are skipped.
What is the session chart?

The session chart is a horizontal strip showing one dot per frame, in the order they were captured. Dot colour represents the filter group (Ha, OIII, SII, Lum, RGB, and so on) — each filter gets its own consistent colour so you can see at a glance whether a quality problem affects one filter or all of them. You can:

  • Click a dot to jump to that frame (the current frame's dot is drawn larger, in the text colour: white in dark mode, black in light mode)
  • Drag across a range of dots to add those frames, after a confirmation, to the Flagged view for closer inspection
  • Filter by folder or filter group using the pill buttons above the chart, to focus on one subset at a time
  • Choose the metric to plot with the buttons above the chart: FWHM, Ecc, SNR, Stars, Sky BG, PSF·S, or Score
  • Switch between dots and bars with the small button at the end of that row; your choice is remembered

The chart makes it easy to spot patterns — a dip in a single filter's dots usually points to a filter-specific problem, while a decline across all colours suggests clouds, wind, or a tracking issue.

Bar mode is unchanged.

How do I reject a frame?

Select a frame in the sidebar and press the reject key (default: X). You can customise this and all other key bindings in Settings → Interface.

Can I reject multiple frames at once?

Yes. Use ⇧+click or ⇧+arrow keys to select a range (highlighted in orange), then press the reject key. The range can be built in the All view or the Flagged view — the behaviour is the same.

What is the Flagged view?

The Flagged view (the segmented control at the bottom of the sidebar) shows a curated pile of frames you have collected for closer inspection, without committing to rejection yet. Think of it as a review queue.

Selection model — two independent concepts:

  • Cursor — the single frame currently shown in the viewer. Plain click or arrow keys move it. It never affects the review queue.
  • Range selection — an orange-highlighted group of frames built with ⇧+click, ⌘+click (add or take out one frame, as in Finder), ⇧+arrow keys, ⌘A (select all visible), ⌘D (clear), or ⌘I (invert). Used for batch operations (add to queue, remove from queue, reject).

Building the review queue (Flagged view):

  • Press F to toggle the flag on the current entry (or the entire orange range if one is active). Press D to deflag everything at once.
  • In All view: select a range (⇧+click, ⌘+click or ⇧+arrow), then press F to add it to the queue.
  • Drag across the session chart to add a run of frames to the queue directly.
  • Auto-Flag — adds all frames that fall below your chosen quality thresholds.
  • The (De)flag toolbar button toggles the flag state of the current entry or range at any time.

Working inside the Flagged view:

  • Plain click — move the cursor (view that frame); clears any orange range.
  • ⇧+click or ⇧+arrow keys — select an orange range for batch operations. ⌘A selects all visible, ⌘D clears the range, ⌘I inverts it.
  • Reject key — rejects the orange range (or the cursor if no range). Rejected frames stay visible so you can undo immediately with the undo key (or the reject key again in toggle mode).
  • F on the orange range — removes those frames from the queue (no rejection).

The review queue persists when you switch between All, Flagged, and Rejected views, and is cleared only by Deflag All (D) or Reset.

What happens to rejected frames?

They are moved into a REJECTED/ subfolder inside the folder they came from. No files are deleted. You can undo a rejection at any time. Rejecting many frames at once runs in the background, with a progress bar; frames that can't be moved (for example a file locked in Finder) are listed in one message.

How do I undo a rejection?

It depends on the Single key reject/undo (toggle) setting in Settings → Interface:

  • Toggle on (recommended): The same key both rejects and un-rejects. Press it once to reject a frame, press it again to undo. This is the simplest workflow — many users assign the spacebar.
  • Toggle off: Reject and undo are separate key bindings, each configurable independently.

In either case, if the REJECTED/ folder becomes empty after an undo, it is removed automatically.

How do I sort the sidebar?

Use the sort dropdown in the sidebar toolbar to choose between Name (the default, reflecting capture order) or any quality metric: FWHM, Eccentricity, SNR, Stars, Sky BG, PSF Signal, or Score. Rejected sorts rejected frames to one end. The up/down arrow button next to it reverses the sort direction. Sorting by quality score with the worst frames at the bottom makes it quick to select and reject the tail of the list as a group.

What is Simple mode vs Geek mode?

Simple mode skips the quality measurements: no metrics, badges or session chart, and the fastest loading. It is useful for a quick visual pass or for users who prefer not to interpret numbers.

Geek mode computes the quality metrics, shows them in the inspector panel on the right, and enables the session chart. For a compact row of metric values above the chart, turn on Show metric chips above session chart in Settings → Display. Toggle between modes with the configured key (default: G) or the toolbar button, which shows the current mode name (Simple or Geek).

What is Auto-Flag?

Auto-Flag lets you set quality thresholds and preview how many frames match before applying. The matching frames are added to the Flagged view so you can inspect them individually and decide which ones to actually reject. Access it from the toolbar.

Thresholds work in one of two modes:

  • Relative (default) — compared with the median of the frame's filter group, e.g. flag frames whose FWHM is more than 1.5× the group median. This adapts automatically to each night's seeing.
  • Absolute — fixed values, e.g. flag frames with FWHM above 3.5 px.

Available criteria: FWHM, eccentricity, star count, SNR, sky background, PSF Signal Weight, and (absolute mode only) quality score. The starting values flag frames with FWHM above 1.5× the median, eccentricity above 0.65, SNR below 60 % or a star count below 50 % of the median: the last two catch haze and thin cloud. Sky background and PSF Signal Weight are off by default; add them to catch moonlight or a brightening sky. Frames with fewer than 10 stars are flagged whenever any check is on. In a filter group with fewer than 3 frames, the checks against the median are skipped; the sheet tells you which groups.

What do I do after culling?

Point your stacking tool (PixInsight, Siril, AstroPixelProcessor, etc.) at the same folder you opened in FITS Blaster. Rejected frames have been moved to a REJECTED/ subfolder and will not appear in a normal folder scan. If your tool also reads subfolders (PixInsight's WBPP with a directory does), turn on Rename rejected files so other programs skip them in Settings → Files & Folders before you reject: the rejected files then end in .rejected and are skipped.

If you change your mind, reopen the folder in FITS Blaster with Include REJECTED folder turned on in the folder panel, select the rejected frames, and undo the rejection before you start stacking.

Can I export a list of frames and their metrics?

Yes. Click Export… in the toolbar to save the loaded frames as a file. The export sheet lets you choose:

  • Format — CSV, tab-separated (TSV), or plain text. CSV and TSV are for spreadsheets and scripts; the plain-text report is padded into aligned columns for reading in a text editor.
  • File paths — absolute paths, paths relative to the folder all frames share, or filenames only.
  • Include rejected frames — adds rejected frames with a status column (kept / rejected).
  • FITS header columns — any header keys you want as extra columns, such as DATE-OBS, EXPTIME, FILTER, FOCUSPOS, or HUMIDITY. Keys that don't appear in any loaded file are dimmed.

In Geek mode the export includes FWHM, eccentricity, SNR, star count, PSF Signal Weight, and score for each frame. Numbers always use a decimal point, whatever your region settings, so the files open correctly in any spreadsheet. Set your defaults in Settings → Export; changes in the export sheet apply to that export only.

You can start working immediately once loading begins — you do not need to wait for the entire set. In colour mode, FITS Blaster renders the full set in greyscale first so you can start culling straight away; both versions are kept in memory so switching between them is instant.

Tips for Power Users

What is the fastest way to cull a large set?
  1. Load the folder in greyscale + geek mode. Greyscale loads faster than colour; geek mode computes quality metrics and populates the session chart.
  2. Glance at the session chart — drag-select any obvious bad runs to flag them, then use Auto-Flag to catch anything you missed.
  3. Switch to the Flagged view. Step through the flagged frames and press the reject key on the ones you want to move to REJECTED/.
  4. For the remainder, switch the sidebar sort to quality score. Your worst frames are now at one end; ⇧+click to select them as an orange range, then press the reject key.

If you only want a quick visual pass without metrics, simple mode loads faster but the session chart is not available.

Can I use the keyboard for everything?

Almost. Arrow keys navigate; ⇧+arrow extends the orange range selection; ⌘A / ⌘D / ⌘I select all, clear, or invert the range; F toggles the flag on the current entry or range; D deflags everything; your configured reject key rejects or toggles. The only things that require the mouse are drag-selecting a range in the chart and clicking filter pills.

Can I have FITS Blaster open while my stacking tool is running?

Yes — FITS Blaster holds no locks on your files. However, avoid undoing rejections while a stacking tool is actively reading the same folder, as moving files mid-stack may confuse the stacking tool.

Can I run FITS Blaster from the command line?

Yes, in the version downloaded from this website (not the Mac App Store version). Run the app's executable with a folder path, and FITS Blaster measures every frame without opening a window and writes a CSV file with the results:

"/Applications/FITS Blaster.app/Contents/MacOS/FITS Blaster" ~/Astro/M31/LIGHT

The folder can be a full path, start with ~, or be relative to the current folder in Terminal; options can come before or after it. By default the CSV is written to frames.csv inside that folder. Progress goes to the terminal, and the path of the CSV is printed when it's done, so you can use it in scripts. Your FITS files are never moved or changed.

Add filter criteria to export only the good frames. As in Auto-Flag, thresholds are relative to the filter group's median by default:

"/Applications/FITS Blaster.app/Contents/MacOS/FITS Blaster" ~/Astro/M31/LIGHT -f 1.5 -e 0.65 -p 0.5 -o ~/Desktop/m31-keepers.csv

This keeps frames with FWHM at most 1.5× the median, eccentricity at most 0.65, and PSF Signal Weight at least half the median. The most useful options:

  • -o output file  ·  -S include subfolders  ·  -r include the REJECTED folder (marked status=rejected)
  • -m rel|abs threshold mode  ·  -f FWHM  ·  -e eccentricity  ·  -n stars  ·  -s SNR  ·  -b sky background  ·  -p PSF Signal Weight  ·  -q score (absolute mode)
  • -P rel|abs path style  ·  -H DATE-OBS,FILTER,… FITS header columns

A mistyped option or value stops with an error instead of being ignored. When some files can't be read, they are listed and left out of a filtered CSV; when no frame passes the filter, the CSV has only the header row. The exit code tells a script what happened (0 done, 1 usage error or no FITS files, 2 the CSV couldn't be written, 3 no frame passes, 4 some files couldn't be read). Run it with --help for the full list. For the beta, use FITS Blaster Beta.app in the path. If you get “permission denied” for a folder in iCloud Drive, give FITS Blaster Full Disk Access in System Settings → Privacy & Security → Full Disk Access.

Privacy & Data

Does FITS Blaster send my images anywhere?

No. All processing happens on your Mac. Your image files never leave your device.

What data does FITS Blaster collect?

None. FITS Blaster does not collect analytics, telemetry, or usage data of any kind. The only network request is the daily update check in the version downloaded from this website, which fetches the list of available versions and sends nothing about you or your images. The Mac App Store version makes no network requests at all; the App Store handles its updates.

Does FITS Blaster require access to my entire disk?

No. FITS Blaster only reads the folders you open, and the only change it ever makes on disk is moving rejected frames into, and back out of, a REJECTED/ subfolder (with .rejected added to their names if you turn that on in Settings → Files & Folders).

  • Mac App Store version — sandboxed by macOS: it can only access folders you choose in the open panel or drag onto the window.
  • Version from this website — not sandboxed, because the command-line mode needs to read any folder path you give it. It still only reads the folders you open. macOS privacy protection still applies: for folders in iCloud Drive you may need to give FITS Blaster Full Disk Access in System Settings → Privacy & Security.
